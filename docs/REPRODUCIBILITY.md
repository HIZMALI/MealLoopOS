# Reproducing the release

Use a Git checkout with Python 3.14.0 and Node 24.13.1 on Windows. `scripts/setup.ps1` creates a new virtual environment, installs the exact 41-package Python lock and npm lock, and imports the bundled official workbook. `npm ci` verifies npm integrity digests; Python pins do not include wheel hashes. Other environments, Linux/cloud deployment and PostgreSQL remain unverified.

## Tests and release gates

From the repository root, with LOCAL mode or `MEALLOOP_MODE` unset:

```powershell
.\.venv\Scripts\python.exe -m pytest
npm.cmd --prefix frontend run typecheck
npm.cmd --prefix frontend run build
.\.venv\Scripts\python.exe -m pip check
npm.cmd --prefix frontend ls --all
.\.venv\Scripts\python.exe scripts\verify_science.py
.\.venv\Scripts\python.exe scripts\prepare_public_demo.py
.\.venv\Scripts\python.exe scripts\release_check.py
.\.venv\Scripts\python.exe scripts\smoke_release.py
.\.venv\Scripts\python.exe scripts\publication_audit.py
```

Run commands individually and stop on any nonzero exit; PowerShell does not automatically stop on native command failures. The complete **398-test suite** remains represented. The release checker fails on missing public documentation, dependency mismatch, changed fingerprints, unclassified API routes, unsafe configuration, isolation/read-only failures or nonreproducible seed/restart behavior. Its gate logic is retained; only obsolete internal-report requirements were replaced by the public methodology/security/reproduction documents.

The HTTP smoke starts fresh-seed, prepared-restart and ephemeral-reseed servers from allowlisted public files. It tests writes/default-deny, Host/Origin rejection, private cohort bounds, all three stateless previews, notice delivery and unchanged DB bytes. It never copies the operator's normal database. Check reports default to ignored `.run/`. A compact executed snapshot is retained in `evaluation/release_verification.json`; it is local evidence, not a provider certification.

## Scientific evidence

`verify_science.py` verifies the public input hashes, creates a disposable official-data database, executes all three evaluators, and compares generated bytes with the historical evidence. It never reads the normal operational DB. It fits only as part of this explicit evaluation command; public startup and previews never fit.

To inspect each output separately after local setup:

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_forecasts.py --output .run/forecast-reproduction.json
.\.venv\Scripts\python.exe scripts\evaluate_decisions.py --output .run/decision-reproduction.json
.\.venv\Scripts\python.exe scripts\evaluate_impact.py --output .run/impact-reproduction.json
```

## Publication and dependencies

`publication_audit.py` scans working and staged bytes independently, every local Git blob, ref/reflog trees and commit metadata. It checks private paths, SQLite signatures and common credential patterns, including bounded XLSX archive members. Ignored runtime contents are not published in its report. Findings contain identifiers rather than secret values. This heuristic and visual screenshot review do not prove absence of secrets or replace independent security assessment.

`scripts/license_inventory.py` rebuilds declarations/notices from installed exact dependencies and the retained source-license supplements. The Windows snapshot contains 41 Python packages and 129 npm lock entries; optional binaries on other platforms require their own review. See `THIRD_PARTY_LICENSES.md`. Dependency advisory checks are time-dependent; rerun `npm audit` and a separate `pip-audit` installation before a new release.

The public distribution preserves every application/test/migration file from development commit `c152279a93e2ee6abfbe2791b43ef7ad536967b4`. Packaging changes are confined to public documentation, output/report paths, a science-verification wrapper and exact-lock setup. The original development tree/history remains separate and intact. Its initial public commit represents a release snapshot, not exclusively human-written or one-commit development.
